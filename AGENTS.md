# Алиасы пользовательских команд

- Когда пользователь пишет `залей ченжи`, считай это явным запросом на локальный коммит текущих изменений репозитория.
- Проверь рабочее дерево и при необходимости создай один или несколько логически разделённых коммитов с краткими содержательными сообщениями.
- Включай только относящиеся к задаче изменения исходного кода; не коммить секреты, временные файлы, результаты сборки и несвязанные пользовательские изменения.
- Не выполняй push, публикацию, создание pull request и не отправляй коммиты в удалённый репозиторий иным способом. Пользователь сделает это самостоятельно.
- Не изменяй и не переписывай существующие коммиты, если пользователь явно об этом не попросил.

# Комментарии в коде

- Пиши новые и существенно переработанные комментарии в коде преимущественно на русском, если только соглашения окружающего файла или внешний API не требуют английского.
- Сохраняй идентификаторы, названия API, ключи настроек, значения протоколов и точный текст диагностических сообщений на исходном языке.

# Форматирование C#

- Оставляй вызов метода на одной строке, пока он остаётся читаемым. Если хотя бы один аргумент переносится на другую строку, размещай каждый аргумент на отдельной строке, а закрывающую скобку — ещё на одной отдельной строке.
- После завершённого многострочного вызова метода добавляй пустую строку перед следующим независимым выражением. Не добавляй пустую строку внутри одного выражения или непосредственно перед закрывающей фигурной скобкой.

# Директивы using в C#

- Размещай директивы `using` в начале файла перед объявлением пространства имён.
- Сначала размещай системные пространства имён с корнями `System` и `Microsoft`, а после них — блок остальных, пользовательских и проектных пространств имён. Эти два блока не перемешивай.
- Внутри каждого блока сортируй пространства имён иерархически и рекурсивно. На каждом уровне сравнивай длину имени текущего сегмента пространства имён. Пространства имён с сегментами одинаковой длины сохраняй в принятом в файле относительном порядке; не вводи для них дополнительную алфавитную сортировку. Родительское пространство имён должно находиться перед своими вложенными пространствами имён.
- Для каждого вложенного уровня применяй то же правило отдельно. Например, после `System.Windows` пространства имён `System.Windows.Data`, `System.Windows.Input`, `System.Windows.Media`, `System.Windows.Controls` и `System.Windows.Threading` располагаются именно в таком порядке.
- Директивы `using` с псевдонимами размещай отдельным последним блоком: после обычных системных и пользовательских пространств имён. Внутри блока псевдонимов определяй порядок по пространству имён в правой части выражения и применяй те же правила рекурсивной сортировки по длине сегментов.

# Форматирование XAML

- Не записывай несколько XAML-элементов или дочерние элементы в одну строку. Каждый открывающий, закрывающий и самозакрывающийся тег размещай отдельно с корректным отступом по уровню вложенности.
- Если у тега нет атрибутов либо есть ровно один атрибут, записывай весь тег в одну строку, например `<ColumnDefinition Width="Auto" />`.
- Если у тега два и более атрибута, оставляй имя тега и первый атрибут на одной строке. Каждый следующий атрибут размещай на отдельной строке и выравнивай его начало по началу первого атрибута. Закрывающий символ `>` или `/>` оставляй в конце строки последнего атрибута.
- Не переноси первый атрибут на строку ниже имени тега. Исключение допустимо только для объективно нечитаемой строки длиной 150 символов или больше, которую невозможно разумно сократить.
